# Развёртывание и эксплуатация

## 1. Требования

| Компонент | Версия | Назначение |
|---|---|---|
| Node.js | 24+ | API и сборка веб-клиента |
| PostgreSQL | 16+ | основная БД |
| Redis | 7+ | очередь конвертации (BullMQ) |
| LibreOffice | 7+ (soffice headless) | конвертация PPTX → PDF |

В dev-окружении Postgres и Redis поднимаются `docker compose` (см. `docker-compose.yml`);
API и конвертация запускаются локально (гибридная схема).

## 2. Первичная установка (dev)

```bash
npm install
npm run setup   # docker compose up -d + prisma migrate dev + seed
npm run dev     # API :3001, веб :5180
```

## 3. Конфигурация

`server/.env` (шаблон — `server/.env.example`):

| Переменная | Описание | Значение по умолчанию |
|---|---|---|
| `PORT` | порт API | 3001 |
| `DATABASE_URL` | строка подключения PostgreSQL | локальный docker |
| `REDIS_URL` | строка подключения Redis | redis://localhost:6379 |
| `JWT_SECRET` | секрет сессий — **обязательно сменить в проде** | dev-значение |
| `STORAGE_DIR` | каталог файлового хранилища | `../storage` |
| `LIBREOFFICE_PATH` | путь к soffice | путь установки на этой машине |
| `WEB_ORIGIN` | разрешённые CORS-источники (через запятую) | http://localhost:5180 |
| `PUBLIC_BASE_URL` | базовый URL фронтенда для QR-ссылок | http://localhost:5180 |

## 4. Прод-развёртывание (ориентир)

1. **БД и очередь**: управляемый PostgreSQL и Redis (или те же docker-контейнеры с томами).
2. **API**: `npm run build -w server` → `NODE_ENV=production node server/dist/main.js`.
3. **Веб**: `npm run build -w web` → раздача статики `web/dist/` любым веб-сервером;
   запросы `/api/*` проксируются на API.
4. **Миграции**: `npm run prisma:deploy -w server` при каждом релизе.
5. **HTTPS**: терминируйте TLS на обратном прокси (nginx/Caddy); cookie автоматически получают
   флаг `Secure` при `NODE_ENV=production`. Обновите `WEB_ORIGIN` и `PUBLIC_BASE_URL` до https-адресов.
6. **Файловое хранилище**: каталог `STORAGE_DIR` — на постоянном томе; интерфейс хранилища
   вынесен так, чтобы можно было перейти на S3 без изменения бизнес-логики.
7. **LibreOffice**: в Linux-контейнере установите `libreoffice --headless` и шрифты
   (например, `fonts-liberation`, при необходимости `ttf-mscorefonts-installer`), укажите
   `LIBREOFFICE_PATH=/usr/bin/soffice`. Для кириллицы важна комплектность шрифтов.

## 5. Резервное копирование

Готовый скрипт: `ops/backup.sh` — дамп БД через `pg_dump` + архив каталога `storage/`,
хранит копии 30 дней. Запуск по cron:

```
0 3 * * * /opt/pulsecheck/ops/backup.sh >> /var/log/pulsecheck-backup.log 2>&1
```

- **БД**: `pg_dump slide_hz | gzip > backup-$(date +%F).sql.gz` по cron; восстановление — `psql < dump`.
- **Файлы**: копирование каталога `storage/` (оригиналы + PNG слайдов). Если оригинал утерян,
  слайды можно перегенерировать из БД-записей, поэтому достаточно инкрементальной синхронизации.
- Проверяйте восстановление на стенде не реже раза в квартал.

## 6. Мониторинг и обслуживание

- **Health-check**: `GET /api/health` — 200 `{ok:true,db:true,redis:true}` или 503 при недоступности
  БД/Redis; вешайте на балансировщик и uptime-мониторинг (Uptime Kuma, Zabbix и т.п.).
- Логи API — stdout (JSON при желании обёрткой pino); аудит значимых действий преподавателей —
  таблица `audit_logs` (вход, загрузка/удаление, запуск/завершение лекций, копирование слайдов,
  импорт, одобрения пользователей).
- Очередь конвертации: `bullmq`-очередь `conversion` в Redis; при отказе задание ретраится
  (2 попытки), презентация получит статус `failed` с текстом ошибки в кабинете.
- Rate-limit: 500 запросов/мин на IP по умолчанию, публичные голосования — строже (60–120/мин).

## 7. Тесты и CI

- `npm test` — требует запущенных docker-контейнеров: тесты поднимают приложение через
  `@nestjs/testing`, используют изолированные БД `slide_hz_test` и Redis db 1.
- Готовый CI-workflow: `.github/workflows/ci.yml` (services: postgres, redis; установка
  LibreOffice; `npm run build` + `npm test` на каждый push/PR). Для CI база тестов создаётся
  через psql и передаётся переменной `TEST_DATABASE_URL`.

## 8. Известные ограничения текущей итерации

- Один экземпляр воркера конвертации на инстанс; массовые загрузки ограничены лимитом файла 300 МБ.
- Обновление результатов — polling (2–5 с); WebSocket/SSE — возможный следующий шаг.
- Полная локализация интерфейса (сейчас русский) отложена по плану.

## 9. Модерация пользователей

Регистрации создают аккаунт со статусом `pending` — до одобрения администратором мутации
(загрузка, опросы, лекции) запрещены guard-ом `ApprovalGuard`, ответы студентов не затрагиваются.
Статусы пользователя: `pending` → `approved` / `blocked`.

- Первый администратор создаётся сидом (`npm run seed`, `admin@slide.local` / `admin12345`) —
  **смените пароль в проде** через страницу «Профиль» после первого входа.
- Аудит одобрений/блокировок пишется в `audit_logs` (`user.approve` / `user.block`).

## 10. Почта и восстановление пароля

- Восстановление пароля: `POST /api/auth/password/forgot` создаёт одноразовый токен (30 минут)
  и отправляет письмо со ссылкой `/reset-password?token=…`. Токены хранятся хешированными,
  одноразовые; смена пароля гасит все выданные токены.
- **SMTP**: переменные `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `MAIL_FROM` в `.env`.
  Если `SMTP_HOST` не задан (dev), письмо выводится в консоль сервера, а ответ API содержит
  `devResetUrl` — **в production обязательно задайте SMTP_HOST**, иначе восстановление работать
  не будет.
